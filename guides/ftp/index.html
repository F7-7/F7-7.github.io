Software

  • WiresharkCapture and analysis
  • VMware Workstation ProRuns both virtual machines
  • Windows Server 2025 (evaluation)Server OS and the IIS FTP service
  • Windows 11 Enterprise (evaluation)Client OS

Windows 7 is no longer available for download; the Windows 11 evaluation does the same job. If you use 32-bit Windows 7, install Wireshark 3.6, the last version that supports it, from the older releases page.

Setup

  1. Install VMware Workstation Pro

    It is free for personal use. The download comes from the Broadcom support portal after you create an account.

  2. Create two virtual machines

    One for the server on the Windows Server 2025 evaluation, one for the client. In VMware's network adapter settings choose LAN Segment and put both machines on the same segment, so they get an isolated network of their own.

  3. Enable the FTP service on the server

    From PowerShell as administrator:

    powershell
    Install-WindowsFeature Web-Ftp-Server -IncludeManagementTools

  4. Install Wireshark on the server

    Keep the Npcap option ticked during setup; Npcap is what captures the packets.

Steps

  1. Give each machine a static IP

    Server 189.120.0.58, client 189.120.0.57. The adapter name differs between machines, so look it up first with the first command:

    cmd
    netsh interface ipv4 show interfaces
netsh interface ipv4 set address name="Ethernet0" static 189.120.0.58 255.255.255.0
    • show interfacesLists the adapter names
    • set address … staticSets a fixed address and mask on that adapter

  2. Create an FTP site in IIS

    On the server open IIS Manager, right-click Sites and choose Add FTP Site:

    text
    Site name:      FTP
Physical path:  C:\inetpub\ftproot
Binding:        189.120.0.58   Port 21
SSL:            No SSL
Authentication: Anonymous
Authorization:  Anonymous users  ·  Read
    • ftprootThe folder the client sees when it connects
    • No SSLThe session is unencrypted, so every command shows up in the capture
    • AnonymousThe client logs in without an account

  3. Put a file in ftproot

    Open Notepad, type anything, and save it inside C:\inetpub\ftproot. In this capture the folder held two files: fahad.txt (7 bytes) and Test.txt (empty).

  4. Start capturing on the server

    Run Wireshark on Windows Server, pick the internal adapter, and start before connecting so you catch the three-way handshake. Then apply the filter:

    wireshark
    ftp || ftp-data || tcp.port == 21
    • ftpControl-channel commands and replies
    • ftp-dataWhat the data channel carries
    • tcp.port == 21Also shows the empty ACK segments

  5. On the client, type the address in File Explorer

    On Windows 7 open Computer, type this in the address bar and press Enter. The ftproot files appear like any folder:

    text
    ftp://189.120.0.58
    • ftp://Opens the control channel on port 21
    • USER anonymous · PASS User@Sent automatically by File Explorer for an anonymous login
    • opts utf8 on · syst · site helpExtra commands Explorer adds on its own; you will see them in the capture

  6. Open the file

    Double-click the file. Explorer sends TYPE I, then PASV, then SIZE and RETR, and opens a new data connection to transfer it.

  7. Stop the capture and save it

    Save as pcapng to keep the timestamps.

Useful Wireshark filters

  • ftp.request.command == "PASV"Passive-mode requests only
  • ftp.response.code == 227The reply carrying the data address and port
  • tcp.flags.syn == 1The start of every connection
  • ftp-dataWhat was transferred

What the capture shows

  • Three-way handshake

    SYN starts at Seq 693140712 and the server answers with Ack 693140713, that is 693140712 + 1.

  • Data port 49672

    227 Entering Passive Mode (189,120,0,58,194,8).
    194 × 256 + 8 = 49672, and in the next frame the client opens a new connection to that port.

  • Data port 49673

    227 Entering Passive Mode (189,120,0,58,194,9).
    194 × 256 + 9 = 49673, and in the next frame the client opens a new connection to that port.

  • The file list

    The data channel carried 99 bytes: 09-19-26 03:59AM 7 fahad.txt 09-19-26 06:01AM 0 Test.txt

  • Downloading an empty file

    RETR Test.txt after the SIZE reply 213 0, so the data connection opened and closed with no data.

  • The password is exposed

    PASS User@ crosses the network in plain text. For an anonymous login it is a placeholder, but a real account would be exposed the same way.

Troubleshooting

530 after PASS

Anonymous login is not enabled in IIS.

Fix: Enable Anonymous Authentication and add an Authorization rule that allows Read.

LIST hangs with no reply

The server firewall blocks the high data ports.

Fix: Set a PASV port range under FTP Firewall Support and open it in the firewall.

425 Can't open data connection

The client cannot reach the data port.

Fix: Check passive mode and that the range is open in the firewall.

File Explorer asks for a user name and password

Anonymous login is off, or the rule does not cover Anonymous users.

Fix: Enable Anonymous Authentication on the FTP site and add an Allow rule for Anonymous users with Read.

Ping between the two machines fails

The VMs are on different VMware networks, or Windows Firewall is blocking ICMP.

Fix: Put both network adapters on the same network (the same VMnet or LAN Segment), and enable the rule File and Printer Sharing (Echo Request - ICMPv4-In).

Wireshark shows no packets

You picked an adapter the traffic does not go through.

Fix: On the start screen pick the adapter whose activity graph moves during the test, and start capturing before you run it.
