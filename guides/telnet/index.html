  • أمر telnet في Windowsعميل Telnet المدمج في Windows

خدمة Telnet Server موجودة حتى Windows Server 2012 R2 وأُزيلت من الإصدارات بعده، لذلك الخادم هنا 2012 R2. وعلى Windows 7 بنسخة 32-bit استخدم Wireshark 3.6.

التجهيز

  1. فعّل عميل Telnet على Windows

    من موجه أوامر بصلاحيات المسؤول:

    cmd
    dism /online /Enable-Feature /FeatureName:TelnetClient

  2. فعّل خادم Telnet على Windows Server 2012 R2

    من PowerShell:

    powershell
    Install-WindowsFeature Telnet-Server
Set-Service TlntSvr -StartupType Manual
Start-Service TlntSvr

التنفيذ

  1. ابدأ الالتقاط على العميل ثم اتصل

    شغّل Wireshark على Windows 7 واختر بطاقة الشبكة، ثم:

    cmd
    telnet 189.120.0.58
    • telnet <IP>يتصل على المنفذ 23 افتراضيًا

  2. اقرأ أول رسالة من الخادم

    21 بايت فيها سبعة طلبات، كل طلب ثلاثة بايتات يبدأ بـ FF (IAC):

    text
    ff fd 25   DO   Authentication Option
ff fb 01   WILL Echo
ff fb 03   WILL Suppress Go Ahead
ff fd 27   DO   New Environment Option
ff fd 1f   DO   Negotiate About Window Size
ff fd 00   DO   Binary Transmission
ff fb 00   WILL Binary Transmission
    • FFIAC: البايت التالي أمر
    • FB / FDWILL / DO
    • FA … F0بداية ونهاية خيار فرعي (SB … SE)

  3. لاحظ حجم النافذة

    داخل رد العميل: ff fa 1f 00 50 00 14 ff f0. القيمتان 0x0050 و 0x0014 تعنيان 80 عمودًا و 20 سطرًا.

  4. تابع محاولة NTLM

    يتبادل الطرفان رسائل NTLMSSP الثلاث داخل خيار Authentication، ثم يرد الخادم بأنه لم يستطع تسجيل الدخول بـ NTLM ويطلب اسم المستخدم.

  5. سجّل الدخول وراقب الحروف

    كل حرف تكتبه يُرسل في مقطع مستقل. حروف اسم المستخدم يعيدها الخادم (Echo)، أما حروف كلمة المرور فيرد عليها بـ ACK فقط. ومع ذلك كل حرف منها يمر على الشبكة بنص واضح.

  6. اكتب exit وأوقف الالتقاط

    بعد الدخول يتفاوض الطرفان على نوع الطرفية، ثم يرسل الخادم الشاشة. exit ينهي الجلسة والخادم يبدأ الإغلاق بـ FIN.

    cmd
    exit

ماذا كشف الالتقاط

  • 7 طلبات في رسالة واحدة

    أول ما أرسله الخادم 21 بايت: 7 أوامر IAC، كل أمر 3 بايتات، قبل أي نص على الشاشة.

  • نافذة 80 × 20

    العميل أعلن حجم شاشته: ff fa 1f 00 50 00 14 ff f0.

  • NTLM ثم الرفض

    ثلاث رسائل NTLMSSP: Negotiate بحجم 57 بايت، ثم Challenge بحجم 255 بايت، ثم Authenticate بحجم 514 بايت. محتوى الرسالتين الأخيرتين مُصفّر في الملف المنشور.
    بعدها رد الخادم: Telnet server could not log you in using NTLM authentication.

  • اسم المستخدم يعود، كلمة المرور لا

    اسم المستخدم 5 حروف، كل حرف في مقطع والخادم يعيده. كلمة المرور 11 ضغطة، والخادم يرد على كل واحدة بـ ACK فقط. لكن الحروف نفسها تمر بنص واضح، لذلك استُبدلت بـ * في الملف المنشور.

  • الطرفية ANSI والشاشة

    بعد الدخول طلب الخادم نوع الطرفية فأجاب العميل ANSI، ثم أرسل الخادم الشاشة كاملة في 506 بايت بأوامر ANSI لتحديد مكان كل سطر.

  • الخادم يغلق أولًا

    بعد exit أرسل الخادم FIN، ثم أغلق الطرف الآخر.

مشاكل وحلول

'telnet' is not recognized

عميل Telnet غير مفعّل.

الحل: فعّل الميزة TelnetClient بالأمر في قسم التثبيت.

Connection refused على المنفذ 23

خدمة TlntSvr متوقفة.

الحل: شغّلها بالأمر Start-Service TlntSvr.

ping بين الجهازين يفشل

الجهازان على شبكتين مختلفتين في VMware، أو جدار الحماية في Windows يمنع ICMP.

الحل: تأكد أن بطاقة الشبكة في الجهازين على نفس الشبكة (VMnet نفسها)، وفعّل قاعدة File and Printer Sharing (Echo Request - ICMPv4-In).

Wireshark لا يعرض أي حزم

اخترت بطاقة شبكة غير التي يمر عليها الاتصال.

الحل: من شاشة البداية اختر البطاقة التي يتحرك مؤشر نشاطها أثناء الاتصال، ثم ابدأ الالتقاط قبل تنفيذ التجربة.

العربية

حلّلت جلسة Telnet بين Windows 7 و Windows Server 2012 R2: تفاوض الخيارات بأوامر IAC، ومحاولة مصادقة NTLM رفضها الخادم، ثم تسجيل الدخول حرفًا حرفًا. أهم ما خرجت به أن كلمة المرور ظهرت كاملة في الالتقاط رغم أنها لا تظهر على الشاشة، وهذا سبب انتقال الإدارة عن بعد إلى SSH.

English

Analysed a Telnet session between Windows 7 and Windows Server 2012 R2: IAC option negotiation, an NTLM authentication attempt rejected by the server, and a character-by-character login. The password was hidden on screen but fully readable in the capture, which is exactly why remote administration moved to SSH.
