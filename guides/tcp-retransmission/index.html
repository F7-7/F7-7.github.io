Steps

  1. S4 is lost

    The client sends 12 bytes starting at 2046860036 and they never arrive. The server has nothing new to acknowledge.

  2. The RTO expires and the segment is resent

    It goes again with the same Seq, Ack and checksum (0xAAB3).

  3. S6 is lost and it happens again

    6 bytes starting at 2046860048, resent with the same checksum (0x4033).

Troubleshooting

Thinking Seq grows with each attempt

Seq marks the bytes' position in the stream, not the attempt number.

Fix: A resent segment always carries the same Seq.
