Setup

  1. Reuse the FTP lab

    This project needs no extra software.

  2. Put a 10 KB file in ftproot

    The file in the capture is 10,240 bytes, all the letter A. This PowerShell command creates an identical one:

    powershell
    Set-Content -Path "C:\inetpub\ftproot\ftp 10kb.txt" -Value ("A" * 10240) -NoNewline

Steps

  1. Capture on the server, then copy the file

    Capturing on the server shows the file before the network card splits it, which is what the results explain. On the client open the address in File Explorer and copy the file to the desktop:

    text
    ftp://189.120.0.58
    • TYPE IExplorer transfers the bytes as they are
    • SIZEAsks the server for the size before downloading
    • PASV, then RETROpens a data connection and requests the file

  2. Follow the data connection

    Use Follow TCP Stream on the port 49672 connection to see the whole file.

    wireshark
    tcp.port == 49672

  3. Check Total Length in the file's frame

    Open the large data frame and look at the IPv4 layer. You will find an unexpected value; the results explain it.

Useful Wireshark filters

  • tcp.len > 1000Large segments only
  • ftp.response.code == 213The SIZE reply
  • tcp.flags.fin == 1 || tcp.flags.reset == 1How the connections close

What the capture shows

  • Size before download

    RETR ftp 10kb.txt was preceded by SIZE, and the reply was 213 10240.

  • The whole file in one frame

    10294 bytes, 10240 of them data starting at Seq 1216553898. The client answers with Ack 1216564138 = 1216553898 + 10240.

  • Why is Total Length 0?

    The capture ran on the server itself. The OS hands the network card one large block, and the card splits it into MSS-sized segments and writes the length (TCP Segmentation Offload). Wireshark saw the block before the split.

  • The close

    The server ends the data channel with FIN, and the client cuts it with RST ACK.

Troubleshooting

Wireshark shows segments larger than 1460 bytes

Expected when capturing on the sending host with offload enabled.

Fix: To see the real segmentation, capture from a third machine or disable Large Send Offload in the adapter settings.

Ping between the two machines fails

The VMs are on different VMware networks, or Windows Firewall is blocking ICMP.

Fix: Put both network adapters on the same network (the same VMnet or LAN Segment), and enable the rule File and Printer Sharing (Echo Request - ICMPv4-In).

Wireshark shows no packets

You picked an adapter the traffic does not go through.

Fix: On the start screen pick the adapter whose activity graph moves during the test, and start capturing before you run it.
